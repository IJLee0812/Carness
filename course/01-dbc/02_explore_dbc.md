아래 탐색기는 opendbc의 Toyota RAV4 DBC를 펼친 것입니다. 왼쪽에서 메시지를 고르면 오른쪽에 다음이 나옵니다.

1. **요약 카드**: ID, 바이트 수, 송신 노드, 실제 로그에서 관측된 버스와 주기
2. **비트 배치**: 8 × 8 격자에서 각 신호가 차지하는 칸. 이름이 적힌 칸이 그 신호의 MSB, 「LSB」가 마지막 비트
3. **신호 표**: `SG_` 줄을 열로 펼친 것
4. **DBC 원문**: 신호를 고르면 그 `SG_` 줄이 강조되고 조각마다 뜻이 풀려 나옵니다

```widget dbc
vehicle = "rav4_2017"
message = "SPEED"
signal = "SPEED"
```

## 해 볼 것

1. `SPEED` 메시지의 `SPEED` 신호를 골라 원문 풀이를 읽어 보세요. 시작 비트 47은 몇 번 바이트의 몇 번 비트인가요?
2. 검색창에 `WHEEL` 을 넣고 `WHEEL_SPEEDS` 를 고르세요. 바퀴 네 개의 신호가 비트 배치에서 어떻게 나뉘어 있나요?
3. `GEAR_PACKET` 의 `GEAR` 신호는 값 정의(`VAL_`)가 있습니다. 숫자 몇이 `P` 인가요?
4. 「로그에 있는 메시지만」을 켜 보세요. DBC에는 있지만 이 주행 로그에는 한 번도 나오지 않은 메시지가 있습니다.

<details><summary>답 보기</summary>

1. 47 = 5 × 8 + 7 이므로 Byte 5의 bit 7입니다. Motorola라서 여기가 MSB, 즉 읽기 시작하는 칸입니다.
2. 16비트씩 Byte 0~1, 2~3, 4~5, 6~7을 차례로 씁니다.
3. `32 "P"` 이므로 32입니다.
4. 이 차량에서 쓰지 않는 메시지이거나, 이 1분 주행 중에 보내지 않은 메시지입니다. DBC는 차종 공통 사전이라 실제 차량보다 넓게 정의되어 있습니다.

</details>
