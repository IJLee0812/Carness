실제 DBC에는 바이트를 통째로 쓰지 않는 신호가 흔합니다. RAV4 조향각 `STEER_ANGLE : 3|12@0-` 처럼 바이트 중간에서 시작해 다음 바이트로 넘어갑니다. 학습용 DBC의 `EX_ODD_BOUNDARY` 메시지가 바로 이 경우를 연습하는 예제입니다.

## Intel: `INTEL_10 : 5|10@1+`

```widget bitlab
vehicle = "example"
message = "EX_ODD_BOUNDARY"
signal = "INTEL_10"
frame = "E0 01 3F C0 00 82 00 00"
mode = "view"
```

시작 비트가 5인데, 풀이는 `1.6`(Byte 1의 bit 6)부터 시작합니다. 이상해 보이지만 Intel 규칙 그대로입니다.

1. Intel의 시작 비트 5는 **LSB**입니다. 신호는 거기서 번호가 커지는 쪽으로 10개, 즉 k 5 ~ 14를 차지합니다.
2. 가장 큰 번호 **k 14 = Byte 1의 bit 6** 이 MSB입니다.
3. 읽기는 항상 MSB → LSB이므로 `1.6` 에서 시작해 `0.5`(시작 비트)에서 끝납니다.

| 순서 | 1 ~ 7 | 8 ~ 10 |
|---|---|---|
| 칸 | Byte 1의 bit 6 ~ 0 | Byte 0의 bit 7 ~ 5 |
| 값 | `0x01` → `0000001` | `0xE0` → `111` |

이어 붙이면 `0000001111` = **15** 입니다.

> [!TIP]
> 10진수로 비유하면, 359라는 수의 위치를 「일의 자리가 어디 있는가」로 정해 두고, 읽을 때는 백의 자리부터 읽는 것과 같습니다. Intel 정의의 시작 비트가 그 「일의 자리」입니다.

## Motorola: `MOTOROLA_10 : 21|10@0+`

같은 위젯에서 신호 칩을 `MOTOROLA_10` 으로 바꿔 보세요.

- 시작 비트 21(Byte 2의 bit 5)이 **MSB**라서 여기서 읽기 시작합니다.
- Byte 2에서 bit 5 → 0으로 6칸을 읽고, 다음 바이트 Byte 3의 bit 7로 넘어가 4칸을 더 읽습니다.
- `0x3F` 의 아래 6비트 `111111`, `0xC0` 의 위 4비트 `1100` → `1111111100` = **1020**

## 정리

| | 시작 비트 | MSB 위치 | 읽기 시작하는 칸 |
|---|---|---|---|
| Intel | LSB | 시작 비트 + 길이 − 1 | MSB (시작 비트가 아님) |
| Motorola | MSB | 시작 비트 | 시작 비트 |
